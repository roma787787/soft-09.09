# Запуск бота с телефона, пошагово

Инструкция рассчитана на то, что компьютера под рукой нет. Всё делается в
Telegram и в браузере Safari или Chrome на телефоне.

Важно понимать: сам бот не может работать «внутри айфона», iOS не даёт
держать постоянно запущенную программу. Поэтому код поедет на облачный
сервер, который работает круглосуточно, а телефон будет пультом
управления.

Что понадобится:

- Аккаунт Telegram (он уже есть).
- Аккаунт GitHub, тот самый, где лежит репозиторий `roma787787/soft-09.09`.
- Банковская карта для хостинга. У Railway есть пробный период, дальше
  порядка пяти долларов в месяц.

Времени на всё: минут пятнадцать.

---

## Часть 1. Создать бота и получить токен

Делается целиком в приложении Telegram.

1. Открой Telegram, в поиске сверху набери `@BotFather` и выбери его.
   У настоящего BotFather стоит синяя галочка.
2. Нажми кнопку **Start** внизу экрана.
3. Отправь команду `/newbot`.
4. BotFather спросит имя бота (*name*). Это просто подпись, которая будет
   видна в шапке чата. Можно написать что угодно, например
   `Bridge Tracker`.
5. Дальше он спросит юзернейм (*username*). Тут правила строгие: только
   латинские буквы, цифры и подчёркивания, и обязательно окончание на
   `bot`. Например `roma_bridge_tracker_bot`. Если имя занято, он попросит
   придумать другое.
6. В ответ придёт сообщение с строкой примерно такого вида:

   ```
   8123456789:AAHkL9vQ2xY-ExampleTokenValue_1234567890
   ```

   Это **токен**, ключ управления ботом. Нажми на него, чтобы
   скопировать.

> **Никому не показывай токен и не выкладывай его в репозиторий.** Кто
> угодно с этим токеном сможет управлять ботом от твоего имени. Если
> случайно засветил, отправь BotFather команду `/revoke`, он выдаст новый.

Ссылку на своего бота BotFather тоже пришлёт, она вида `t.me/твой_бот`.
Сохрани её, она понадобится в конце.

## Часть 2. Поднять бота на хостинге

Открывай браузер на телефоне. Ниже описан Railway, потому что его панель
нормально работает с мобильного и он умеет собирать проект прямо из
GitHub. Подойдёт любой хостинг, умеющий запускать Node.js.

1. Зайди на `railway.com`, нажми **Login** и выбери вход через **GitHub**.
   Разреши доступ, когда GitHub спросит.
2. Нажми **New Project**, затем **Deploy from GitHub repo**.
3. В списке репозиториев найди и выбери `roma787787/soft-09.09`. Если его
   нет в списке, нажми **Configure GitHub App** и дай Railway доступ к
   этому репозиторию.
4. **Самый важный шаг.** Открой созданный сервис, зайди в **Settings**,
   найди раздел **Source** и в поле ветки (*Branch*) выбери:

   ```
   claude/bridge-contracts-tracking-tool-72hf0k
   ```

   По умолчанию хостинг берёт основную ветку, а весь код лежит именно в
   этой. Без этого шага сборка упадёт или задеплоится пустота.
5. Перейди на вкладку **Variables**, нажми **New Variable** и добавь:

   | Имя | Значение |
   |---|---|
   | `TELEGRAM_BOT_TOKEN` | токен из шага 6 первой части |

   Больше ничего добавлять не нужно, у остальных настроек есть рабочие
   значения по умолчанию. Следи, чтобы в конце токена не было лишнего
   пробела (бот его теперь обрезает сам, но лучше вставить чисто).
6. Там же в **Settings** найди раздел **Volumes**, добавь диск и укажи
   путь монтирования:

   ```
   /app/data
   ```

   Это нужно, чтобы список отслеживаемых контрактов не стирался при
   каждом обновлении. Шаг необязательный: без него бот работает, но после
   передеплоя команды `/track` придётся повторить.
7. Дождись окончания сборки. Открой вкладку **Deployments**, выбери
   последний деплой и нажми **View Logs**.

Бот запустился, если в логах появилась строка:

```
[startup] bot launched, long polling active
```

## Часть 3. Проверить, что всё живое

1. Вернись в Telegram и открой своего бота по ссылке `t.me/твой_бот`.
2. Нажми **Start**. В ответ придёт справка со списком команд.
3. Отправь проверочную команду. Это реальный адрес моста Portal в
   Ethereum:

   ```
   /info 0x3ee18B2214AFF97000D974cf647E7C347E8fa585 ethereum
   ```

Должна прийти карточка с зелёным кружком и надписью
`Portal (мост Wormhole)`, списком фактов о контракте и связанными сетями.

Если карточка пришла, значит работает вообще всё: и сам бот, и связь с
блокчейн-нодами.

## Часть 4. Если что-то пошло не так

| Что видишь | В чём причина | Что делать |
|---|---|---|
| Бот не отвечает на `/start` | Неверный токен, в логах ошибка `401` | Перепроверь `TELEGRAM_BOT_TOKEN` в Variables, скопируй токен заново у BotFather |
| Сборка падает с ошибкой | Скорее всего выбрана не та ветка | Settings → Source → ветка `claude/bridge-contracts-tracking-tool-72hf0k` |
| В логах `no start command` | Хостинг не понял, как запускать | Проверь, что в Settings команда запуска `npm start`, а сборки `npm run build` |
| `/info` отвечает «не удалось распознать» на все сети | Бесплатные публичные ноды режут запросы | Подключи свои RPC, см. часть 5 |
| Деплой сразу останавливается | Сервис создан как web и ждёт HTTP-порт | В настройках выбери тип **Worker** / **Background worker**, бот не слушает порт |
| Список `/list` опустел после обновления | Не подключён диск | Часть 2, шаг 6 |
| В `/diag` много сетей с «нет ответа», а времена у всех почти одинаковые | Резолвинг доменов упирается в очередь, а не в ноды | Бот сам ставит `UV_THREADPOOL_SIZE=32`; если сетей стало сильно больше, добавь эту переменную в Variables со значением `64` |

Если ошибка непонятная, скопируй текст из логов и пришли мне, разберу.

## Часть 5. Свои RPC, чтобы работало стабильно

По умолчанию бот ходит в бесплатные публичные ноды. Они медленные и
ограничивают частоту запросов, из-за чего `/info` иногда будет отвечать,
что ничего не найдено. Лечится бесплатным ключом.

1. Зарегистрируйся на `alchemy.com` (бесплатного тарифа хватает с
   запасом).
2. Создай приложение (*App*) для нужной сети и скопируй ссылку вида
   `https://eth-mainnet.g.alchemy.com/v2/КЛЮЧ`.
3. В Railway на вкладке **Variables** добавь переменную для этой сети:

   | Сеть | Имя переменной |
   |---|---|
   | Ethereum | `ETHEREUM_RPC_URL` |
   | Arbitrum | `ARBITRUM_RPC_URL` |
   | Optimism | `OPTIMISM_RPC_URL` |
   | Base | `BASE_RPC_URL` |
   | Polygon | `POLYGON_RPC_URL` |
   | BNB Chain | `BSC_RPC_URL` |
   | Avalanche | `AVALANCHE_RPC_URL` |
   | Unichain | `UNICHAIN_RPC_URL` |
   | Ink | `INK_RPC_URL` |
   | Linea | `LINEA_RPC_URL` |
   | World Chain | `WORLDCHAIN_RPC_URL` |
   | Mode | `MODE_RPC_URL` |
   | Berachain | `BERACHAIN_RPC_URL` |
   | Blast | `BLAST_RPC_URL` |
   | Celo | `CELO_RPC_URL` |

Добавлять все сразу не обязательно, начни с Ethereum и той сети, которая
нужна чаще всего.

Есть ещё две необязательные настройки для слежения:

- `TRACK_POLL_INTERVAL_MS` — как часто проверять новые события, в
  миллисекундах. По умолчанию `60000`, то есть раз в минуту. Меньше
  пяти секунд поставить нельзя.
- `TRACK_INITIAL_LOOKBACK_BLOCKS` — на сколько блоков назад смотреть при
  первом включении слежения. По умолчанию `1000`.

## Шпаргалка по командам

| Команда | Что делает |
|---|---|
| `/info <адрес> [сеть]` | Определяет протокол моста и показывает конфигурацию. Без указания сети ищет по всем семи |
| `/track <адрес> [сеть]` | Включает оповещения о новых событиях контракта в этот чат |
| `/untrack <адрес> [сеть]` | Выключает оповещения |
| `/list` | Показывает, за чем сейчас идёт слежение |
| `/diag` | Проверяет связь с нодами всех сетей |
| `/help` | Справка |

Названия сетей можно писать сокращённо: `eth`, `arb`, `op`, `base`,
`polygon` или `matic`, `bsc` или `bnb`, `avax`.

---

## Что делать дальше

Обновления кода подтягиваются автоматически: как только в ветке
появляется новый коммит, Railway пересобирает и перезапускает бота сам.
Ничего нажимать не нужно.
